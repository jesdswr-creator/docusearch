## 2. Verified GOOD (no action needed)

**Wiring / interlinking**
- All 6 `SearchBar` signals, both `ResultsPane` signals, both `PreviewPane` signals, all 3
  `TagsNotesPane` signals, and all 8 `SettingsDialog` signals (apply/restore/reset/AI
  weight/threshold/topK/embed/rebuild) are connected to real `MainWindow` slots. No
  silently-dead new-style connects; zero legacy string-based `SIGNAL()/SLOT()` macros.
- All 23 Lucide icon names requested via `loadLucideIcon/Pixmap` exist both on disk and in
  `resources/app.qrc`; `:/themes/base.qss` and `:/icons/DocuSearch-256.png` resolve.
- Keyboard navigation in results works (`currentRowChanged`, not just clicks); double-click →
  `fileActivated`; sort combo wired.
- Sidebar routing (`onSidebarClicked`) correctly dispatches Duplicates / Stats / Settings /
  Help / About, with the `QSignalBlocker` guard that fixed the old "Help click also ran
  Duplicates" re-entrancy bug.
- Frameless-window plumbing is solid: `WM_NCHITTEST` edge resize + `WS_THICKFRAME` restore,
  min/max buttons via explicit lambdas, maximize glyph refresh.
- FTS5 injection safety: user tokens pass through `fts5Quote()` (proper `""` escaping).
- OCR helper (`docusearch_ocr_helper.exe`) — resolved relative to `applicationDirPath()`,
  built as its own target, verified + staged by CI, smoke-tested in the workflow.
- MSI versioning is properly single-sourced: CI parses `project(VERSION)` from CMakeLists and
  passes `-d ProductVersion`; the `.wxs` fallback is correctly wrapped in `<?ifndef?>`.
- No broken relative links across README / HELP / FAQ / INSTALL / BUILD / docs/*.
- No `qDebug()` leftovers; no hardcoded absolute paths in `src/` (only placeholder strings).
- CI: builds on windows-2022, runs the 10-suite ctest matrix, deploys Qt + PDFium + ONNX +
  BGE model, builds portable ZIP + MSI, attests provenance. Well above average.

## 3. Known-dormant code (documented, intentional — verify before v2)

- `indexer_` is **never constructed**; `onStart/Stop/Pause/ResumeIndexing` are guarded legacy
  slots ("indexer disabled in this build") and `IndexingProgressWidget`'s Pause/Stop buttons
  are hidden with their `pauseRequested/resumeRequested/stopRequested` signals unconnected.
  Consistent and safe, but it's ~500 lines of dead surface worth pruning eventually.
- `SearchBar::refreshRequested` is connected but never emitted (`refreshBtn_` removed;
  F5 shortcut still triggers `onRefresh()` directly). Harmless dead wire.
- `resources/themes/dark.qss` / `light.qss` are referenced by nothing (only `base.qss` is
  compiled in) yet are still shipped by the CMake `install(DIRECTORY resources/themes ...)`
  rule. Dead weight in the installer.

## 4. Remaining production-readiness recommendations (not changed — judgment calls)

1. **Log growth is unbounded** — `Logger::init` creates one file per day
   (`docusearch_YYYYMMDD.log`) at **Debug** level, and nothing ever prunes old files.
   Recommend: Info level for release builds + delete logs older than ~14 days at startup.
2. **`QtConcurrent::run` lambdas capture `this`** (BGE init, others). If the window is
   destroyed while a worker runs, that's a use-after-free window on exit. Consider a
   `QFutureWatcher` owned by the window, or guard with a shared "alive" token.
3. **Stats dialog under-reports DB size** — counts only `docusearch.db`, not `-wal`/`-shm`
   (WAL can be hundreds of MB mid-scan).
4. **`scripts/build-release.ps1` has drifted from CI**: it harvests with
   `-cg AppFilesHarvest` into `DocuSearch.Harvest.wxi`, but `DocuSearch.wxs` references
   `ComponentGroupRef Id="HarvestedFiles"` (CI uses `scripts/generate-harvest.ps1`, which is
   correct). A local MSI build via `build-release.ps1` will fail to link. Fix or delete it.
5. **Non-Windows configure claims**: comments say non-Windows CI sanity builds "configure
   cleanly", but `dbghelp` is linked unconditionally and the OCR-helper target (WinRT
   headers) is added on all platforms — configure passes, build would not. Wrap both in
   `if(WIN32)` if cross-platform configure checks matter.
6. **Help content lives in a hardcoded QMessageBox** while HELP.md/FAQ.md ship in the
   install folder — consider linking the dialog to those files so help stays in one place.
7. **No code-signing step in CI** (self-signed cert script exists). Unsigned exe + MSI means
   SmartScreen warnings for every download — the single biggest UX blocker for distribution.

## 5. Verdict

**Close to production-ready** for a v1.x Windows utility: wiring/routing is clean and
complete, CI/packaging is genuinely strong, and crash handling (SEH translator + minidumps +
single-instance guard + splash safety net) is thoughtful. The one real defect — settings and
geometry silently lost via the primary Close button — is fixed in this branch. Ship-blockers
remaining are operational, not code: code-signing (item 7) and log hygiene (item 1).

# Addendum (follow-up session): Settings wiring deep-trace

User report: "some settings are not taking effect." Confirmed. Every
`AppSettings` field was traced dialog → persistence → runtime consumer.

## Bugs found & fixed

1. **Apply vs OK asymmetry (the big one).** The Apply button ran a slim
   handler (save + re-theme only); OK ran the full handler (OCR-pool push +
   indexedDrives diff → watch/unwatch/purge/scan). Worse, Apply overwrote
   `settings_`, so a subsequent OK diffed new-vs-new and **silently skipped
   the folder scan/purge** — "Apply then OK" lost folder changes entirely.
   → Both buttons now route through one shared `MainWindow::applyNewSettings()`.

2. **Excluded Folders ignored by both scanners.** `scanFolderFast` passed an
   empty exclude list to `walkDirectory`, and the hourly auto-scan passed
   `QStringList()`. Only live watcher events honored the setting.
   → Both walks now receive `settings_.excludedFolders`; newly excluded
   folders are also purged from the index immediately on apply.

3. **Excluded Extensions consumed by nothing.** Saved, round-tripped,
   never consulted. → Now gates all three ingest paths (Add-Folder scan,
   hourly scan, live watcher) via a normalized set (".ISO"/"iso"/" Iso " equal).

4. **"Monitor indexed drives for live changes" was a placebo.** No consumer;
   the FileWatcher always ran. → Honored at startup and live-toggled on
   apply (stop() / re-arm addWatches()).

5. **"Worker threads" was a placebo.** OCR pool hardcoded to 2 threads.
   → Pool size now `clamp(maxWorkerThreads, 1, 4)`; tooltip states it takes
   effect on next launch (pool size is fixed at construction).

6. **CPU throttle settings didn't take effect via Apply** (OK-only since
   v1.7.9). → Fixed by the shared path (item 1).

7. **"Run OCR during re-indexing" checkbox hidden.** Its only consumer is
   the legacy Indexer, which is never constructed in this build. Field still
   round-trips (same convention as the hidden darkMode checkbox).

## Still-dormant by design
- `tessdataPath`, `ocrLanguage`, `thumbnailSize`, `lazyOcrEnabled`: retained
  for settings-file compatibility, no active consumer.
